# المعمارية: نسخة تجريبية نظيفة

## الطبقات، من السؤال للإجابة
1. السؤال بالعربي يدخل على `agent.py`.
2. الـ agent يطابق السؤال مع مقياس معتمد فقط، مش مع استعلام حر.
3. `metrics.py` يبني استعلاما من قالب ثابت، ببارامترات فقط: الفرع، والفترة.
4. `security.py` يراجع الاستعلام كله قبل التنفيذ: SELECT فقط، جملة واحدة، جداول مسموحة فقط، ولا كلمة محظورة في أي جزء من الاستعلام، بما فيه WHERE وJOIN وORDER BY.
5. قاعدة البيانات تحسب الرقم، والـ agent يشرح النتيجة فقط.
6. الإجابة تخرج بالشكل الثابت: الرقم، والفترة، وتعريف المقياس، والمصدر، ودرجة الثقة.
7. لو مفيش مقياس مطابق، أو الداتا مش كافية، الإجابة تكون امتناعا واضحا، مع ذكر ما هو ناقص.

## لماذا هذا التصميم؟
- الموديل لا يحسب، فلا يخترع أرقاما.
- لا يوجد SQL حر من المستخدم، فلا يوجد حقن أو وصول لجدول غير مسموح.
- كل مقياس ليه تعريف واحد مكتوب، فالسؤال المتكرر يطلع نفس الرقم.
- الداتا التجريبية لا تحتوي على أسماء عملاء أو هواتف أو مرتبات أو كلمات سر.

## ما الذي لم يبنى بعد، عن قصد؟
- لا واجهة ويب كاملة، ولا تسجيل دخول، ولا تعدد مستأجرين.
- لا اتصال بموديل خارجي لحساب الأرقام.
- لا اتصال بنظام Vo Technology الحقيقي.
كل نقطة من دول مرحلة مستقلة، بنقطة مراجعة خاصة بها.
